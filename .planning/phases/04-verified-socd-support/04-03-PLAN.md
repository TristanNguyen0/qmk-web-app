<objective>
Record the SOCD module version on every build, the way the QMK commit and generator version already
are, so a downloaded firmware image traces to the exact SOCD implementation that produced it.

Purpose: D-03. The project's reproducibility claim is that any artifact can be traced back to the
inputs that made it. SOCD adds a new input — a versioned first-party community module whose C is
compiled into the image — and today nothing on the build record names it. Without this, two
artifacts built from the same configuration revision under different module versions are
indistinguishable after the fact.

Output: an additive migration, an extended completion contract implemented by both queue stores,
and a worker write path that threads the module version from generation to the build record.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → database | The worker writes build provenance under the restricted `qwa_worker` role |
| build record → owner | The build summary is served to the configuration's owner and to nobody else |
| migration → schema | A migration file executes with the migrating role's privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10 | Repudiation | firmware artifact provenance | medium | mitigate | The module version is persisted on the build row at completion, so an artifact can be traced to the SOCD implementation that produced it; a null value means SOCD was not enabled, never "unknown" |
| T-04-11 | Elevation of Privilege | migration 004 | high | mitigate | The migration adds one nullable column and contains no grant, revocation, removal or data-modifying statement; asserted by the comment-stripped keyword check in the acceptance criteria. The `qwa_worker` grant set is unchanged |
| T-04-12 | Information Disclosure | build summary | low | accept | The module version is a first-party version string with no secret content, and the summary is already owner-scoped by the Phase 2 ownership predicate |
| T-04-13 | Tampering | client-supplied provenance | medium | mitigate | The version is read from the module package constant inside the worker process, never from the configuration or the request; a client cannot influence what is recorded |
| T-04-SC | Tampering | module bytes behind the recorded version | high | mitigate | The recorded version is only meaningful because `verifySocdModuleIntegrity()` refuses to materialize any module file whose SHA-256 differs from its reviewed digest (D-00e) |
</threat_model>
