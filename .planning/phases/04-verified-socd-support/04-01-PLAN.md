<objective>
Land the accepted Phase 4 implementation from branch `worktree-phase-4-socd` (commit `683270f`)
onto `main`, and prove on main that a SOCD configuration compiles to real firmware in the isolated
build image.

Purpose: this phase is reconciliation plus gap closure, not greenfield construction (04-CONTEXT.md
§ Phase Boundary). Every later plan edits files that only exist on main after this landing. Landing
first, and proving the whole vertical slice before touching anything, means an integration problem
surfaces after one commit rather than after four plans of gap-closure work built on an unproven
merge.

Output: main carries the SOCD module package, the domain policy/pair/keycode tables, the
prerequisite-driven capability gate, the generator's module emission, the compile matrix, the SOCD
panel, and ADR 0005 — with an honest README claim and a hardware-evidence record waiting to be
filled.

Requirement traceability for D-00b: locked decision D-00b supersedes not only the ROADMAP scope note
but also the literal reading of `claude.md` § SOCD Cleaner integration clause 3 (and its verbatim
paraphrase, `REQUIREMENTS.md` § REQ-socd-policy-choices acceptance clause 3) — "generate the exact,
minimal required includes, feature flags, callbacks, and configuration definitions through versioned
templates". That clause is satisfied here, not waived: the `modules: ["qmkweb/socd_cleaner"]` array
plus the four substituted keycode tokens in `keymap.json` **are** the exact, minimal required
configuration definition, emitted through the versioned generator template and pinned by a versioned
module (`SOCD_MODULE_VERSION` + reviewed SHA-256 digests, D-00e). The includes, feature flags and
callback wiring the clause names are then produced by QMK's own data-driven community-module tooling
from that declaration — which is what makes them exact and minimal — rather than by hand-written C
the generator would have to guess at and keep correct across catalog revisions. Emitting that C
ourselves would be the larger, less minimal, and less verifiable reading of the same clause, and
would spend Phase 3's no-generated-C property for nothing (ADR 0005; D-00a, D-00b).
</objective>
