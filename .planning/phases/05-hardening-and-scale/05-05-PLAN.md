<objective>
Close the three session-layer holes that make every other abuse control meaningful.

**D-12:** minting a fresh anonymous session is the cheap step that defeats every per-owner
quota, and it happens in exactly one place — the `onRequest` hook in `apps/api/src/session.ts`.
Bounding it is the single IP-scoped control this phase adds; once it is bounded, the existing
two-concurrent / twenty-per-hour per-owner limits do their job again and a per-IP build quota is
largely redundant.

**D-14:** that limit is worthless without a correct client IP. There is no `trustProxy` and no
use of `request.ip` anywhere in the API today. Configured wrong in one direction, every user
collapses into the proxy's address; wrong in the other, any client claims any IP by setting a
header. Both failures are silent, so start-up fails loudly instead.

**D-04:** `apps/api/src/server.ts` carries a hardcoded session-secret fallback that is only
guarded in production. A secret that guessable would let anyone mint a cookie for any owner id
and read another session's configurations. It goes, in every environment.

Purpose: criterion 1 of the phase, the half 05-01 does not cover.
Output: an IP-bounded session-issuance path that cannot lock a visitor out of the read-only site,
a required secret, an explicitly-configured trusted hop, and the API's first session test file.
</objective>

## Premise correction, and the decisions made here

**Correction to D-04's second clause.** D-04 asks to "set `SameSite` explicitly rather than
inheriting a browser default." `apps/api/src/session.ts` line 97 **already** sets `SameSite=Lax`,
with a comment explaining the choice over `Strict`. That half of D-04 is already satisfied; this
plan verifies and pins it with a test rather than changing it. The real change D-04 asks for is
the removal of the secret fallback in `server.ts`.

**Discretion — the session-issuance limit's value (RESEARCH.md § Open Questions 1).**
`SESSION_LIMITS.issuancePerIpPerHour` is set to **120**, over a rolling one-hour window. A
legitimate visitor mints exactly one session per browser per year, because the cookie's `Max-Age`
is a deliberate one year — so 120 first-time visitors per hour from one address comfortably
covers an office or campus behind a single NAT, which is the case D-12 explicitly asks to protect.
On the other side, it caps the fresh-session churn an attacker needs to route around the
per-owner quotas at 120 per hour per address, and the global queue-depth cap from 05-01 remains
the backstop that does not care how many identities are in play.

**A limitation that must be written into the code, not just noticed.** The counter is
in-process, so with more than one API process the effective limit is 120 multiplied by the
process count. That is acceptable precisely because it is not the load-bearing control: the
global build cap is enforced in Postgres and is correct across processes. Say this in a comment
next to the constant, so the next person does not mistake the IP limit for the thing holding the
line.

**A new transport-level code, not a new domain error code.** A session-issuance refusal is not
`BUILD_QUEUE_LIMITED` — reusing that code would make it a lie and would break the diagnostic
reference `REQ-error-codes` promises. The domain `ErrorCode` enum in `packages/domain/src/errors.ts`
is fixed by `claude.md` and is **not** extended. Instead `RATE_LIMITED` joins
`BAD_REQUEST | NOT_FOUND | INTERNAL_ERROR` in `ApiErrorBody`'s code union in
`apps/api/src/errors.ts`, where transport-level conditions already live.

**No package-legitimacy checkpoint here.** `@fastify/rate-limit` came back OK from the
legitimacy audit in RESEARCH.md — official Fastify-org package, 2.6M weekly downloads, published
well outside the recency heuristic's window. The five OpenTelemetry packages did not, and their
checkpoint lives in 05-07.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → reverse proxy → Fastify | The client address is asserted by a header across this boundary; whether it can be trusted depends entirely on `trustProxy` |
| anonymous visitor → session issuance hook | The one place an identity comes into existence, and the one step that defeats every per-owner quota |
| environment → process start-up | A missing or weak secret here is an authorization bypass for every session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
