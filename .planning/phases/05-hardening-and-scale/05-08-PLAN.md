  <action>
    Write `docs/deployment-requirements.md`, in the prose style of the runbooks. It is the answer
    to "what does this need from me before I point strangers at it", and until now that answer was
    spread across four runbooks, two ADRs and a source-file header.

    Structure it as requirements, each stating three things: what must be provided, what fails
    without it, and **how loudly** — because this phase deliberately made some failures loud and
    left others silent, and the difference is the useful information.

    Cover at minimum:

    - **`QWA_SESSION_SECRET`**, required in every environment with no fallback anywhere, at least
      32 characters, with the command that generates one. Failure: the process exits at start-up
      with a message naming the variable. State what a weak or shared secret would allow, since
      that is why the fallback was removed.

    - **A reverse proxy that sets the forwarded-for header, and `QWA_TRUST_PROXY` naming that
      hop.** Give the accepted forms — an address, a CIDR, or a comma-separated list — and state
      that a boolean value is rejected on purpose. Failure in production: the process exits.
      Failure if the proxy does not actually set the header, or sets it without stripping an
      inbound one: silent, and the two silent failure modes are opposite — every user collapsing
      into one address, or any client claiming any address. Say both.

    - **`QWA_OTEL_EXPORTER_URL` and a collector**, optional. Unset means telemetry is inert and the
      application is unchanged. Point at `docs/runbooks/observability.md` rather than restating the
      query set.

    - **A log sink, and its retention window.** The structured retention events are how an operator
      answers what retention deleted and when, so the sink's retention window must outlast the
      horizon of that question. Record the trigger for adding a `retention_events` table, which is
      exactly the point where it does not.

    - **A Postgres backup schedule and a restore-drill cadence**, pointing at
      `docs/runbooks/backup-restore.md`, and stating plainly that artifacts are not backed up and
      why that is sound rather than an omission.

    - **A CI runner and branch protection**, pointing at `docs/runbooks/ci-runner.md`, and
      restating D-06's constraint in the deployment's own terms: the self-hosted runner must never
      execute fork pull requests, which is acceptable in a solo repository and becomes a hard
      constraint the day it is not.

    - **The identity constraint**, from ADR 0006: sessions are anonymous, work is tied to a cookie,
      and the deployment inherits that as a user-facing property it must not misrepresent.

    Close with a **tunable limits** section listing the numbers this phase chose and the trigger
    for revisiting each: the global queue-depth cap and worker count; the session-issuance limit
    and the number of API processes; the matrix size cap. Present each as a starting value with a
    reason, which is what they are — not as a finding.

    Add a link to this document from `README.md`'s operations area, so it is reachable from the
    front door rather than only by knowing it exists.
  </action>
